# ADR-0004: `validate` is opaque to the implementer

**Status:** Accepted
**Date:** 2026-04-22

## Context

The validate tool will grow to include linters, formatters, typecheckers,
security scanners, and project-specific correctness checks. If the
implementer can see which tool failed and why, two problems follow:

1. **Teach-to-the-test.** The agent learns to suppress warnings (e.g.,
   add `# noqa`) instead of fixing the underlying issue.
2. **Targeted bypass.** A prompt-injected agent that knows which checks
   run can craft output that passes them while still being malicious.

The user explicitly wants the agent to get pass/fail plus enough context
to fix the issue without learning what validate is made of.

## Decision

Validate returns a structured response:

```json
{
  "ok": false,
  "run_id": "abc123",
  "hints": [
    {"path": "src/user.py", "line": 42, "message": "Remove unused symbol."},
    {"path": "src/auth.py", "line": 10, "message": "Handle None return from lookup()."}
  ]
}
```

Hints are generated by an **abstraction layer** in the validate service
that:

- Strips tool names and tool-specific jargon (`ruff`, `mypy`, `bandit`).
- Normalizes messages to a small set of generic forms.
- Suppresses any detail that would reveal *why* a check exists.

The implementer never sees raw tool output, exit codes of individual
tools, or the list of tools that ran.

The agent knows only: "validate said pass" or "validate said fail, here
are generic hints."

## Consequences

- Building the abstraction layer is nontrivial. Every new tool needs a
  mapping to generic hints. That's accepted work.
- Some hard-to-fix errors will have vague hints; the agent may retry
  more. Loop budgets (ADR-0009) bound this.
- Debugging "why did validate fail" is harder for humans. Mitigation:
  the audit log contains raw tool output (not given to the agent) that
  humans can inspect.

## Alternatives considered

**Surface raw tool output.** Rejected — defeats the opacity goal.

**Return only a boolean with no hints.** Rejected — starves the agent
of the information it needs to fix real issues, making loops worse.

**Opacity by obscurity (same tools, rename them).** Rejected — security
by obscurity is weak; the abstraction must be real, not cosmetic.
